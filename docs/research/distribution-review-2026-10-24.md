## Concrete fix: developer PDB path in plugin

The candidate's `dinput8.dll` contains one actual RSDS CodeView record naming
the absolute developer checkout and user profile. Merely excluding `.pdb` files
from the ZIP did not remove that path. The agent's observed `D:\a\_work\...`
strings belong to Microsoft's self-contained runtime, not this developer's
machine; they are not evidence of private project files in the package.

`src/KotorCoop.Plugin/KotorCoop.Plugin.csproj` now passes
`/PDBALTPATH:dinput8.pdb` to the native linker. The real PDB remains beside the
native build output. `tools/publication/package_policy.py` now parses the
plugin's PE debug directory and actual CodeView records, and requires the
basename `dinput8.pdb`. It handles PE32/PE32+, RSDS/NB10 and bounded file-backed
RVAs, and rejects malformed records. It does not scan the agent's runtime text
for arbitrary path-like strings.

Validation:

- All 18 focused package-policy tests passed, including developer paths,
  malformed debug data, PE32/PE32+, RSDS/NB10 and unrelated runtime strings.
- The real old candidate parsed successfully and was correctly refused by the
  new basename guard. Do not publish that candidate under the updated policy.
- A separate MSVC `/DEBUG` fixture linked with the exact option contains
  `dinput8.pdb` in CodeView and retains its separate `private-symbols.pdb`.
  Evidence: `artifacts/distribution-review-native-cccad788ee8b40299f31cfe18c884e73/`.
- MSBuild item evaluation includes the option; the installed .NET 10.0.13
